# Генератор оффлайн-лицензионных кодов JiraTime

Вреднный механизм оффлайн-лицензирования через передаваемый код активации (Ed25519,
подтверждается в приложении публичным ключом без сети). Набор скриптов в этой папке
позволяет выдавать коды владельцам продукта.

## Состав

| Файл | Назначение |
|---|---|
| `license_core.py` | Общая логика сборки/подписи кода, используется и CLI, и GUI |
| `generate_key.py` | Одиноразовая генерация пары ключей (при первой настройке) |
| `generate_code.py` | CLI-генератор кодов (для скриптов/автоматизации) |
| `license_gui.py` | Десктопное GUI-приложение (Tkinter) для ручной выдачи кодов, с историей и комментарием |

## Установка

```bash
cd tools/license-codegen
pip install -r requirements.txt
```

## Первый запуск — генерация пары ключей

```bash
python generate_key.py
```

Создаёт `license_private.key` (приватный ключ, **не коммитить**, в `.gitignore` уже добавлен)
и выведет в консоль публичный ключ в base64. Готовую строку
`const LICENSE_PUBLIC_KEY_B64 = "..."` нужно вставить в `src-tauri/src/license.rs` и пересобрать
приложение. Приватный ключ храните отдельно в безопасном месте (не в репозитории).

## Выдача кода пользователю

### Вариант 1 — GUI (рекомендуется)

```bash
python license_gui.py
```

Открывается окно с:

- полем **«Komу / для чего код»** (необязательный комментарий, называется перед
  генерацией и сохраняется вместе с кодом в истории — удобно потом посмотреть,
  кому выдан какой код);
- кнопками-пресетами (7 дней / 1, 3, 6 месяцев / 1 год) и полем для
  произвольного числа дней;
- кнопкой **«История выданных кодов…»** — открывает таблицу со всеми когда-либо
  сгенерированными кодами (дата, срок, комментарий, код) с возможностью повторного
  копирования любого из них в буфер обмена.

Сгенерированный код автоматически копируется в буфер обмена — его остаётся вставить
в окно активации в основном приложении.

#### Сборка в один `.exe` для Windows (запуск без Python)

```bash
pip install -r requirements.txt
pyinstaller --onefile --noconsole --name JiraTimeKeygen license_gui.py
```

Готовый файл появится в `dist/JiraTimeKeygen.exe`. Переносите его в любую папку на
своём компьютере и запускайте двойным кликом. При первом загрузке он сам
предложит создать пару ключей, если `license_private.key` рядом ещё нет. **Важно**:

- `license_private.key` и `license_history.json` создаются/обновляются **рядом с exe-файлом**, поэтому
  при переносе приложения на другой компьютер/в другую папку переносите оба файла
  вместе с exe, иначе вы лишитесь доступа к ключу и истории;
- рекомендуется держать exe в отдельной парке (например, `C:\JiraTimeKeygen\`), чтобы
  `license_private.key` не смешивался с другими файлами;
- делайте бэкапы `license_private.key` и `license_history.json` отдельно — при утере
  папки восстановить историю выданных кодов без них невозможно.

### Вариант 2 — CLI (для автоматизации/скриптов)

```bash
python generate_code.py --preset month_1
python generate_code.py --days 45
```

Доступные пресеты: `trial_7`, `month_1`, `month_3`, `month_6`, `year_1`. CLI вариант не
пишет в историю GUI (`license_history.json`) — он для быстрых разовых выдач без
требования вести учёт.

## История выданных кодов (GUI)

Каждый код, сгенерированный через `license_gui.py`, добавляется в `license_history.json`
(рядом со скриптом/exe) с полями: дата/время выдачи, срок (дни), комментарий, сам
код и grant_id. Файл никогда не коммитится (в `.gitignore`) — это чисто локальный журнал того,
кто выдаёт коды, и не содержит ничего секретного. Открыть историю в любой момент можно
кнопкой «История выданных кодов…» в главном окне.

## Формат кода

Каждый код — это base32-представление блоба `payload || signature`, где:

- `payload` = `version:u8(1) || days:u16 LE || grant_id: 16 байт (UUID4)` — 19 байт
- `signature` = Ed25519-подпись `payload` приватным ключом — 64 байта

Итого 83 байта → 133 символа base32 без padding, сгруппированные четвёрками для
удобного ввода (`XXXX-XXXX-...`). Формат синхронизирован с `src-tauri/src/license.rs`
основного приложения, который валидирует подпись при активации.

## Безопасность

- `license_private.key` — единственный секрет. Утеря его, любой сможет выпускать валидные коды.
- Желательно хранить его в менеджере секретов или зашифрованном архиве, а не просто на диске.
- Оффлайн-лицензирование по коду — временное решение; grant_id в принципе позволяет
  в будущем сделать revoke-лист при переводе на серверную схему.
