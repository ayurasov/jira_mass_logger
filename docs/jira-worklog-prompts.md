## Как использовать этот набор промптов

Последовательность из 10 промптов для AI-ассистента (Cursor/Claude Code/Windsurf и т.п.) для десктопного приложения **JiraTime** — массовое заполнение worklog в Jira с подтяжкой встреч из Exchange-календаря. Стек — **Tauri 2 + Rust backend + Vue 3/Vite фронтенд**.

**Целевые платформы: Windows 10 и Windows 11 (x64).** Все промпты ниже, начиная со второго, учитывают Windows-специфику: путь к пользовательским данным (`%APPDATA%`/`%LOCALAPPDATA%`), WebView2 runtime, Windows Credential Manager, автозапуск через реестр/Task Scheduler, Toast-уведомления, сборку MSI/NSIS, поведение антивируса/SmartScreen и особенности временных зон Windows.

---

### Промпт 1 — Инициализация проекта и архитектуры

```
Создай новый десктопный проект на Tauri 2 (Rust backend) с фронтендом Vue 3 + Vite + Pinia + TypeScript.
Название приложения: JiraTime.
Целевые ОС: Windows 10 и Windows 11 (x86_64-pc-windows-msvc), сборка через MSVC toolchain.
Структура: 
- src/ (Vue-компоненты, роуты, Pinia store)
- src-tauri/ (Rust-команды: jira_client.rs, exchange_client.rs, db.rs, scheduler.rs)
- локальная БД SQLite (через tauri-plugin-sql или rusqlite) для хранения:
  - профилей подключения к Jira (base_url, email, api_token/PAT, тип: Cloud/Server)
  - профиля подключения к Exchange (EWS URL, учётные данные или OAuth-токен)
  - шаблонов массового трекинга (issue_key, описание, часы, дни недели, период)
  - кэша последних worklog-записей
  - пользовательских настроек (тайм-зона, рабочие часы, праздники/выходные)
БД храни в стандартной Windows-папке приложения (%APPDATA%/JiraTime через tauri path API), не в директории установки.
Настрой безопасное хранение секретов через OS keychain — на Windows это Windows Credential Manager (крейт keyring использует его нативно), не храни токены в открытом виде в БД.
Настрой светлую/тёмную тему (синхронизацию с системной темой Windows 10/11), системный трей с быстрым доступом "Залогировать сегодня" и автозапуск при старте системы через tauri-plugin-autostart (запись в реестр Run, а не Task Scheduler).
Проверь, что установщик подтягивает Microsoft Edge WebView2 Runtime (обязателен для Tauri на Windows) — либо bundled, либо evergreen-загрузчик.
Выведи итоговую структуру папок и ключевые Cargo/npm зависимости.
```

### Промпт 2 — Подключение к Jira (Cloud и Server/Data Center)

```
Реализуй Rust-модуль jira_client.rs для подключения к Jira REST API v3 (Cloud) и API v2 (Server/Data Center).
Функции:
1. test_connection(base_url, email, token, instance_type) — проверка авторизации через GET /rest/api/3/myself.
2. get_projects() и get_issues_by_jql(jql) — для автокомплита задач при выборе issue.
3. get_worklog(issue_key, date_from, date_to) — получение существующих worklog по задаче/задачам за период (используй /rest/api/3/issue/{key}/worklog, а для массовой выгрузки за период — эндпоинт worklog/updated + worklog/list, чтобы не делать по 1 запросу на issue).
4. add_worklog(issue_key, started_at, time_spent_seconds, comment) — POST /rest/api/3/issue/{issueIdOrKey}/worklog.
5. update_worklog(issue_key, worklog_id, payload) и delete_worklog(issue_key, worklog_id).
6. bulk_add_worklogs(list_of_entries) — с очередью запросов, ограничением параллелизма (rate limit Jira Cloud ~ учитывай 429 и Retry-After заголовок), retry с экспоненциальной задержкой и детальным логом успех/ошибка на каждую запись.
Авторизация: Basic Auth (email + API token) для Cloud, Bearer PAT для Server/Data Center.
Для Cloud учти, что comment в worklog должен быть в формате Atlassian Document Format (ADF), а не plain text — добавь конвертер строки в минимальный ADF-объект.
HTTP-клиент (reqwest) настрой с rustls (не native-tls/OpenSSL), чтобы не зависеть от системных сертификатов и корпоративных TLS-инспекторов на Windows-машинах; предусмотри опцию доверия корпоративному root CA, если компания использует SSL-инспекцию на прокси.
Учти корпоративный HTTP-прокси Windows (считывание системных настроек прокси из реестра/WinINet) — добавь fallback на переменные окружения HTTP_PROXY/HTTPS_PROXY и настройку прокси в UI, так как многие корпоративные Windows-сети требуют явный прокси для внешних HTTPS-запросов.
Время started формируй с учётом Windows-таймзоны пользователя (получай через chrono-tz/системную настройку, а не жёстко хардкодь offset), чтобы избежать сдвига часов при смене летнего/зимнего времени.
Добавь юнит-тесты на конвертацию ADF и на retry-логику (мокни HTTP-клиент), запускаемые в CI на Windows-раннере (windows-latest в GitHub Actions).
```

### Промпт 3 — Мастер массового трекинга (ядро продукта)

```
Спроектируй и реализуй экран "Массовая фиксация времени" (Bulk Log Wizard) — главную фичу приложения.
Пользовательский флоу в 4 шага (степпер, прогресс-бар сверху):
1. Выбор задачи Jira: поле с автокомплитом (дебаунс 300мс, поиск через JQL "text ~ query" среди последних использованных и избранных задач), плюс возможность вставить прямую ссылку/ключ задачи.
2. Выбор периода: date-range picker с быстрыми пресетами ("эта неделя", "этот месяц", "последние 2 недели", "с даты Х по дату Y"), чекбоксы дней недели (по умолчанию пн-пт включены, сб/вс выключены), переключатель "исключить праздники/нерабочие дни" (список праздников — настраиваемый, с возможностью импорта производственного календаря РФ).
3. Параметры записи: количество часов на день (число или выбор из пресетов 1/2/4/8), текстовое описание worklog с поддержкой сохранённых шаблонов текста (переменные вида {date}, {week}, {issue} подставляются автоматически), время начала работы в течение дня (чтобы Jira записывала конкретный час, а не только дату).
4. Предпросмотр и подтверждение: таблица со списком ВСЕХ записей, которые будут созданы (дата, день недели, часы, описание), с возможностью убрать/поправить отдельные строки перед отправкой, индикатор суммарных часов, предупреждение о конфликтах если на эту дату+задачу уже есть worklog.
После подтверждения — прогресс отправки с построчным статусом (успех/ошибка/повтор), финальный отчёт с возможностью экспортировать лог операции.
Сохраняй использованный набор параметров как "шаблон" для повторного применения одним кликом в будущем.
Date-picker и системные диалоги (сохранение экспортированного лога) реализуй через нативный Windows Save-диалог (tauri-plugin-dialog), а не веб-эмуляцию — это привычнее для пользователей Windows 10/11 и корректно работает с длинными путями и кириллицей в именах файлов.
Учти масштабирование интерфейса Windows (125%/150%/200% DPI, часто используется на ноутбуках с Windows 11) — все размеры задавай в rem/относительных единицах, протестируй вёрстку степпера и таблицы предпросмотра при HiDPI.
```

### Промпт 4 — Таблица worklog с точечным редактированием

```
Реализуй экран "Мой worklog" — редактируемую таблицу (используй AG Grid Community или TanStack Table + кастомные inline-editable ячейки) со следующими возможностями:
- Колонки: дата, день недели, задача (issue key + summary), часы, описание, время начала, статус синхронизации с Jira.
- Группировка по неделям с автоматической суммой часов на неделю/день и подсветкой дней, где сумма < 8 часов или > 8 часов (настраиваемая норма).
- Inline-редактирование по клику на ячейку (часы, описание, время начала) — при сохранении сразу отправляется update_worklog в Jira, с optimistic UI и rollback при ошибке.
- Быстрое удаление строки (delete_worklog) с подтверждением.
- Быстрое дублирование строки на другую дату.
- Фильтры: по задаче, по диапазону дат, по проекту.
- Полнотекстовый поиск по описанию.
- Кнопка "Обновить из Jira" (принудительный ре-фетч за выбранный период) и фоновая автосинхронизация раз в N минут (настраиваемо, можно выключить).
- Экспорт таблицы в CSV/Excel — сохраняй файл через нативный Windows-диалог "Сохранить как", по умолчанию в кодировке UTF-8 с BOM (чтобы кириллица корректно открывалась в Excel на Windows без дополнительных настроек импорта).
Обработай edge-кейсы: конфликт версий (если запись изменили в самой Jira параллельно — показать diff и дать выбрать какую версию оставить), потеря сети (очередь несинхронизированных изменений с индикатором и повтором, учти, что Windows может резко переводить ноутбук в спящий режим — обрабатывай событие "пробуждение системы" для форс-ресинхронизации).
Проверь работу тач-скролла и колеса мыши в таблице на Windows-тачпадах (precision touchpad) — инерционный скролл не должен конфликтовать с inline-редактированием ячеек.
```

### Промпт 5 — Интеграция с Microsoft Exchange календарём

```
Реализуй модуль exchange_client.rs для получения встреч из корпоративного календаря Microsoft Exchange/Outlook.
Поддержи два варианта подключения (выбор в настройках):
1. Microsoft Graph API (современный, рекомендуемый) — OAuth2 через MSAL (Authorization Code flow с PKCE для десктопа), scope Calendars.Read, запрос GET /me/calendarview?startDateTime=X&endDateTime=Y для получения событий за период.
2. EWS (Exchange Web Services) — для устаревших on-premise Exchange без Graph API, через SOAP-запрос FindItem с CalendarView, Basic/NTLM авторизация (NTLM особенно актуален в корпоративных Windows Active Directory-доменах — используй крейт с поддержкой NTLM/Negotiate, либо системный WinHTTP, который на Windows подхватывает Kerberos/NTLM автоматически через AD-контекст текущего пользователя).
Функции:
- get_calendar_events(date_from, date_to) — возвращает список встреч (тема, начало, конец, длительность, участники, категория/цвет, ссылка на онлайн-встречу если есть).
- Фильтрация: исключать встречи с "Отклонено" статусом, исключать полностью пустые/фоновые события (Free/OOF), опционально исключать встречи короче N минут.
- Кэшируй события локально на день, с ручным refresh.
Authorization Code flow для MSAL на Windows реализуй через системный embedded WebView2 (не внешний браузер по умолчанию), с fallback на loopback-редирект (http://localhost:PORT) для случаев, когда компания блокирует embedded-браузер политиками AD/Intune.
Храни refresh-токен OAuth в защищённом хранилище (тот же keyring/Windows Credential Manager, что и Jira-токены), реализуй автоматическое обновление access-токена.
Добавь экран настроек подключения с тестовой кнопкой "Проверить доступ к календарю" и явным сообщением, если корпоративная политика Windows/Intune блокирует OAuth-редирект или embedded-браузер.
```

### Промпт 6 — Умное сопоставление встреч с задачами Jira и автозаполнение

```
Создай экран "День из календаря" — сводку встреч за выбранный день/неделю из Exchange рядом с формой быстрого трекинга.
Функциональность:
1. Список встреч дня в виде таймлайна (визуально, как в календаре) с длительностью каждой.
2. Для каждой встречи — предложение задачи Jira на основе:
   - истории: если тема встречи содержит текст, ранее сопоставленный с конкретным issue, предложить его автоматически (храни таблицу правил сопоставления "паттерн темы -> issue_key", редактируемую пользователем);
   - regex/keyword правил, настраиваемых пользователем (например, все встречи с "Sprint Planning" -> задача проекта X, все встречи с префиксом "[PROJ-123]" в теме -> сразу нужный issue);
   - ручного выбора, если авто-сопоставление не сработало.
3. Кнопка "Затянуть в worklog" на каждую встречу — создаёт запись worklog с часами = длительность встречи (округление до 15/30 минут — настраиваемое), описанием = тема встречи (с возможностью отредактировать перед сохранением), временем начала = время начала встречи.
4. Массовая кнопка "Затянуть весь день/неделю" — применяет сопоставление и округление ко всем встречам сразу, с экраном предпросмотра перед отправкой (как в Промпте 3).
5. Индикатор "непокрытого" времени в рабочий день (встречи + существующий worklog < нормы часов) с подсказкой сколько часов ещё нужно залогировать и на какую задачу (дефолтная/последняя используемая).
Время встреч из Exchange/Graph приходит с учётом временной зоны организатора/сервера — явно конвертируй в локальную временную зону Windows-пользователя (через системный таймзон-провайдер) перед отображением и перед формированием поля started для Jira, чтобы избежать типичной ошибки сдвига на несколько часов при разных зонах Outlook и Windows.
Учти повторяющиеся встречи (recurring meetings, рассылаемые Exchange как отдельные экземпляры) — не дублируй правило сопоставления на каждый инстанс серии, сопоставляй по общему шаблону темы серии.
```

### Промпт 7 — Настройки, шаблоны и правила автоматизации

```
Реализуй единый экран "Настройки" с разделами:
1. Подключения — управление профилями Jira (можно несколько инстансов) и Exchange, тест соединения, статус токенов, кнопка "Открыть папку данных" (открывает %APPDATA%/JiraTime в Проводнике Windows для диагностики).
2. Рабочий график — норма часов в день, рабочие дни недели, часовой пояс (список системных таймзон Windows), список праздников (с автоимпортом производственного календаря по стране, ручное добавление отгулов/отпусков, которые нужно исключать из массового трекинга и не учитывать в подсчёте нормы).
3. Шаблоны описаний — CRUD для текстовых шаблонов с переменными ({date}, {issue}, {week_number}, {meeting_title}), сортировка по частоте использования.
4. Правила автосопоставления встреч с задачами — таблица правил из Промпта 6, drag-and-drop приоритет правил, тестовый режим "проверить правило на истории встреч".
5. Избранные задачи — закреплённый список issue для быстрого доступа в мастере массового трекинга.
6. Уведомления — напоминание в конце дня/недели, если worklog не заполнен до нормы — реализуй через нативные Toast-уведомления Windows 10/11 (Action Center) с помощью tauri-plugin-notification, с кликабельным действием, открывающим приложение на нужном экране.
7. Автозапуск и поведение при закрытии — настройка "свернуть в трей при закрытии окна" (крестик не завершает процесс, а сворачивает) как отдельный переключатель, привычный для Windows-приложений с треем.
8. Экспорт/импорт настроек в JSON для переноса между машинами (сохранение/чтение через нативные Windows-диалоги выбора файла).
Все поля с валидацией и понятными сообщениями об ошибках, автосохранение без отдельной кнопки "Сохранить" где это уместно.
```

### Промпт 8 — Дашборд аналитики трекинга

```
Добавь стартовый экран-дашборд с виджетами:
- Диаграмма часов по дням за текущую/прошлую неделю с сравнением план/факт (норма часов).
- Разбивка часов по задачам/проектам за выбранный период (donut или stacked bar chart).
- Календарная heatmap-визуализация заполненности worklog за последние 3 месяца (по аналогии с GitHub contribution graph) — быстро видно "дырки".
- Список дней с недозаполненным/незаполненным worklog за текущий месяц с кнопкой быстрого перехода к мастеру массового трекинга на эту дату.
- Метрика "среднее время экономии": сколько записей создано через bulk-мастер против ручного ввода (для мотивации).
Используй Chart.js или ECharts, обеспечь плавные анимации и адаптацию под тёмную/светлую тему, включая автоопределение системной темы Windows 10/11 (light/dark из реестра personalize) при первом запуске.
Протестируй рендеринг графиков в WebView2 (Chromium-based, но со своими нюансами версии рантайма) — убедись, что нет визуальных артефактов и производительность анимаций приемлема на слабых корпоративных ноутбуках Windows.
```

### Промпт 9 — Надёжность, синхронизация и offline-режим

```
Усиль приложение для надёжной работы:
1. Реализуй локальную очередь операций (create/update/delete worklog) в SQLite с полями статус (pending/syncing/synced/failed), количество попыток, текст последней ошибки.
2. Фоновый воркер (Rust async task через tokio) обрабатывает очередь при наличии сети, с exponential backoff и уважением к Jira rate-limit заголовкам (429 + Retry-After).
3. Индикатор сети/статуса синхронизации в шапке приложения (иконка: онлайн/офлайн/синхронизация/ошибка) с деталями по клику; для определения статуса сети используй Windows-специфичные сигналы (NLA — Network Location Awareness) через reqwest health-check, а не только наличие интерфейса.
4. Полный offline-режим: можно готовить массовые записи и редактировать таблицу без сети, всё уйдёт в очередь и отправится при восстановлении соединения; корректно обрабатывай переход Windows в сон/гибернацию и последующее пробуждение (событие пробуждения должно триггерить немедленную проверку очереди).
5. Логирование всех операций с Jira API (уровень debug/info/error) в файл с ротацией в %LOCALAPPDATA%/JiraTime/logs, экран "Логи" в приложении для диагностики проблем пользователем, плюс кнопка "Открыть папку логов" в Проводнике.
6. Механизм graceful-деградации если Jira API вернул неожиданную схему ответа (например, кастомные поля worklog в конкретной инсталляции) — не крашить приложение, показывать понятную ошибку.
7. Учти поведение Windows Defender/корпоративного антивируса: избегай частой записи множества мелких файлов на диск (используй единый SQLite-файл, а не файлы на каждую операцию), чтобы не попадать под эвристику подозрительной активности.
Напиши интеграционные тесты на сценарий: оффлайн создание 20 записей -> восстановление сети -> успешная синхронизация всех записей с корректным порядком, запускаемые на windows-latest в CI.
```

### Промпт 10 — Полировка UX, онбординг и упаковка релиза

```
Финальный проход по продукту:
```

## Ключевые технические заметки

**Формат даты/времени в Jira worklog.** Поле `started` в API v3 требует строгий формат `yyyy-MM-ddTHH:mm:ss.SSS±HHmm` — при массовой генерации записей на "нужный час" критично формировать это поле явно с учётом Windows-таймзоны пользователя, а не полагаться на дефолт.

**Формат комментария в Jira Cloud.** REST API v3 ожидает комментарий worklog в формате Atlassian Document Format (ADF, JSON-структура), а не простую строку — конвертер строка→ADF нужен уже на этапе Промпта 2.

**Массовое чтение worklog.** Для таблицы (Промпт 4) эффективнее использовать связку `worklog/updated` + `worklog/list`, что снижает число запросов и риск упереться в rate limit.

**Rate limiting и повторные попытки.** Jira Cloud возвращает 429 с заголовком `Retry-After` — очередь массовой отправки должна уважать этот заголовок и делать экспоненциальный backoff.

**CORS и архитектура запросов.** Все обращения к Jira REST API и Microsoft Graph должны идти через Rust backend (Tauri commands), а не напрямую из Vue-фронтенда.

**Microsoft Graph vs EWS для календаря.** Для облачного Exchange (Microsoft 365) используйте Graph `calendarView`; EWS/NTLM оставляйте fallback для on-premise без Graph-доступа — на Windows NTLM/Kerberos через AD-домен работает нативнее через WinHTTP.

**Windows-специфика (сводно).**
- Данные приложения — `%APPDATA%/JiraTime` (роумящиеся настройки/БД) и `%LOCALAPPDATA%/JiraTime` (логи, кэш), никогда не пишем в директорию установки Program Files.
- Секреты — Windows Credential Manager через крейт `keyring`.
- Обязателен Microsoft Edge WebView2 Runtime — evergreen bootstrapper в установщике плюс offline-фолбэк.
- Автозапуск — запись в реестре `HKCU\...\Run` через `tauri-plugin-autostart`, а не только Task Scheduler.
- Уведомления — нативные Toast через Windows Action Center.
- Сборка — таргет `x86_64-pc-windows-msvc`, установщики MSI/NSIS, код-сайнинг для обхода SmartScreen.
- Сеть — учитывать корпоративные прокси (WinINet/переменные окружения) и NLA-статус сети; TLS через rustls.
- DPI/масштабирование — тестировать при 125-200% на Windows 11.
- Энергосбережение — обрабатывать сон/пробуждение системы для форс-ресинхронизации очереди.
